# 게임 리뷰 댓글 이벤트 자동화

## 확인한 자료

- `스토브 이벤트.mhtml` 및 `network-log-2026-10-01T11-51-56.har`.
- 공개 목록 API: `GET /eventhub/v1.0/promotion/events/ON?page=0&service_id=STOVEINDIE`.
- 2026-10-01 확인 대상: 이벤트 1914, 게시글 14523486, 배너 노출 기간 2026-10-01 ~ 2026-10-04.
- 등록 API: `POST /cwms/v1.0/article/{articleId}/comment`, `caller-id: storee-cp`.
- HAR의 스티커 HTML, `attach_info`, `request_id: CM`, `view_mode: EDITOR` 형태를 사용한다.
- 이모티콘 최근 사용 저장은 댓글 등록과 별개이므로 실행하지 않는다.
- 댓글 등록 성공은 플레이크 지급 증거가 아니다. 별도 보상 요청과 예상 수익 합산을 하지 않는다.

## 실행 조건과 상태 표시

전체 자동화가 `reviewEvent` 상태를 수집해 실행 가능한 경우에만 직렬 작업을 계획한다. 상태 새로고침은 조회만 수행하며, 탭 방문과 댓글 POST는 전체 자동화에서만 실행한다. 자동 복구 작업에는 포함하지 않는다.

리뷰 이벤트 작업은 다른 작업 그룹 뒤에서 실행한다. 기존 백그라운드 라운지 댓글 작업이 끝난 뒤 기존 댓글 간격(11초)을 대기해 두 API의 댓글 전송이 겹치지 않게 한다. 대기 이후 이벤트 상태와 날짜를 다시 조회한다.

스토어의 한국어 FLAKE 이벤트 중 배너 제목이 일치하는 대상을 찾고 전체 이벤트 페이지를 조회한다. 대상이 없으면 건너뛰고, 여러 대상이나 잘못된 링크·날짜는 확인 필요로 처리한다. 링크는 `https://page.onstove.com/quarter/kr/view/{숫자 ID}`만 허용한다.

매번 `expose_start_at`, `expose_end_at`, `status`를 조회한다. 이 날짜는 배너 노출 기간이며 보상 정책의 확정 자료는 아니다. 한국 시간의 시작일 이상·종료일 이하이고 ONGOING일 때만 실행한다. 현재 기간이면 2026-10-05 00:00 KST부터 건너뛴다. 날짜를 고정하지 않아 연장·대상 변경을 반영한다.

대상 리뷰를 실제 백그라운드 탭으로 열고 대기한 뒤 목록, 댓글 권한, 계정과 기존 댓글을 재확인한다. 마지막 비동기 조회 이후에도 댓글 POST 직전에 한국 시간 날짜를 다시 검사한다. 열린 리뷰 탭은 성공·실패·건너뜀 모두 닫는다. 탭 대기는 실제 사용자의 독서나 보상 인정 여부를 증명하지 않는다.

대시보드는 참여 전, 댓글 등록 완료, 등록 결과 확인 대기, 기간 종료, 권한 없음, 확인 필요를 표시한다. 기간과 대상 리뷰 링크도 표시하고 보상 수령 완료로 표시하지 않는다.

## 중복 방지

- CWMS 커뮤니티 계정의 `member_no`와 댓글 작성자의 `member_no`를 비교한다. 라운지 profile ID로 비교하지 않는다.
- 댓글을 최대 100페이지(페이지당 20개) 조회한다. 이전 페이지의 본인 댓글도 작성 시각에 관계없이 참여로 처리한다. 조회 누락·반복·한도 초과는 댓글 작성을 막는다.
- `stove-review-v1:{memberNo}:{articleId}` 키로 localStorage에 기록한다. 날짜가 바뀌거나 같은 글에 새 이벤트 번호가 붙어도 자동으로 다시 작성하지 않는다.
- Web Locks로 같은 계정·게시글의 동시 실행을 막는다. 저장소·잠금이 없으면 작성하지 않는다.
- POST 전에 pending 기록을 저장하고 다시 읽어 저장 성공을 확인한다. 응답 오류나 타임아웃에서는 추가 POST 없이 댓글 목록만 재조회한다.
- 서버의 본인 댓글을 확인하면 confirmed를 기록한다. 확인되지 않으면 pending을 유지해 새로고침·재실행 시 재전송을 막는다. confirmed 기록은 댓글이 삭제돼도 남는다.
- 수동으로 작성하거나 다른 브라우저에서 작성한 댓글은 서버 댓글 조회로 중복을 막는다. 별도 브라우저에서 동시에 시작하는 경쟁은 브라우저별 잠금으로 완전히 막을 수 없다.

## 검증 범위

API 스키마, 전체 자동화 계획과 스냅샷, 한국 시간 날짜 경계, 수동 댓글, 계정·이벤트 변경, 기록 저장 실패, 요청 결과 유실, 동시 탭, 대시보드 표시를 테스트한다. 배포 userscript를 jsdom에서 실행해 상태 새로고침의 조회 전용 동작과 전체 자동화의 1회 댓글·재실행 건너뜀을 검증한다. 테스트는 네트워크를 모의 처리하며 실제 계정 댓글을 추가하지 않는다. 로그인 환경의 댓글·보상 지급은 이 검증에 포함하지 않는다.
