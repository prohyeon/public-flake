# 오늘의 1등 부스트 미션

MY홈 대시보드에서 서버의 부스트 진행도, 잔여 횟수, 미션 조건과 보상 수령 여부를 조회한다. 상태 새로고침은 GET 요청만 사용하며 후보 조회나 부스트를 실행하지 않는다.

전체 자동화는 활성 미션의 부스트 조건이 0/1이고 잔여 횟수가 있을 때 후보를 2초 간격으로 5회 조회한다. 마지막 응답의 `score`를 비교하며 배열 순서나 이전 조회의 최고점을 사용하지 않는다. 같은 `generated_at`이 반복될 수 있고 서버의 집계를 강제로 갱신하는 것은 아니다. 10분 이상 오래된 집계, 조회 실패, 집계 시각 역전은 실행을 중단한다.

당일 KST에 작성된 공개 게시글 중 이벤트 참여에 동의한 일반 유저 게시글을 대상으로 한다. 본인 글, 이미 부스트한 글, 공식/BOT 글, 잘못된 응답은 제외한다. 실행 직전 계정·미션·잔여 횟수를 다시 확인한다.

부스트는 `PUT /stadium-api/v1.0/boost/{article_id}`, 보상은 `POST /stadium-api/v1.0/missions/{mission_id}/reward`이며 모두 본문이 없다. `caller-id: lounge`, Bearer 인증과 X-UUID를 사용한다. HTTP 성공 외에 응답 `code: 0`과 필수 필드를 검사한다.

부스트는 한 번만 요청하고 서버 진행도 또는 해당 글의 BOOST 상태를 조회하여 확인한다. 댓글은 기존 작업과 병행하되, 미션 보상은 백그라운드 댓글 작업까지 완료된 뒤 모든 조건을 재조회해서 수령한다. 이미 1/1인 미션도 조건이 충족되면 보상만 수령할 수 있다. 다른 조건을 채우기 위한 추가 댓글이나 게시글 작성은 이 모듈이 수행하지 않는다.

계정·미션별 Web Locks 잠금으로 탭 간 실행을 직렬화하고, localStorage에 실행 직전 기록을 남긴다. 부스트/보상 응답이 불확실하면 기록을 유지하고 조회로만 확인한다. 페이지를 새로고침하거나 자동화를 다시 눌러도 다른 글에 부스트하거나 보상을 재요청하지 않는다. 인증 정보는 기록에 저장하지 않는다. 잠금 또는 저장소를 사용할 수 없으면 실행을 중단한다. 날짜가 바뀐다는 이유로 미션 실행 기록을 초기화하지 않는다.

3,000 플레이크 수령은 매일 지급이라고 가정하지 않으며 활성 미션 ID와 서버의 `is_rewarded`를 따른다. 수익 합계에는 성공 응답에서 확인된 플레이크 금액만 더한다. 불확실한 수령 금액을 추정해 더하지 않는다.

검증은 HAR 형식의 응답을 이용한 API/워크플로 테스트, 오류·중복 실행·KST 날짜 경계 테스트, 배포 userscript의 대시보드 및 전체 자동화 시뮬레이션으로 수행한다. 테스트는 실제 계정에 부스트 또는 보상 요청을 전송하지 않는다.
